- Review guide and UI areas: [README.md](README.md). Answers per review item: [README.md, Review items](README.md#review-items).

## How to read the tables

- **What changed** describes behaviour against the base, not the commit history.
- **Why** gives the reason in one or two sentences, then the commit as a reference. The reason comes from a review item, an owner decision or fault report, a commit message, a code comment, a design record or a work-session record. "Reason not recorded" means none of these states it.
- Review IDs: `R1`-`R25` = review notes and `I1`-`I7` = inline comments of 2026-11-17. `F1`-`F14` = performance feedback of 2026-11-20. Code review items of 2026-11-18 use their own IDs (`TX1`, `IS-4`, ...). "Owner" = the design owner of this PR.
- **Evidence** gives the code location. Every row in the funds, keys and storage groups was checked in the source at that location. "Not verified by line" means the row comes from a diff reading only.
- "Test: none" means no Jest test or committed check script exercises the new behaviour. Jest status: [DIFFERENCES_FROM_UPSTREAM.md](DIFFERENCES_FROM_UPSTREAM.md#jest-status).
- No row changes key derivation, hash construction or encryption algorithms. Changes in the keys group are about order of steps, prompts, error codes and fail-closed checks.

## Read these first

These changes carry the highest risk, or they are where the PR now follows upstream again after review.

1. **Send rules are upstream's.** An amount above the balance is refused. When amount plus fee is above the balance, VRPC preflight lowers the output by the fee, as upstream does, and Confirm says so (I5 rule (a) kept as upstream by the owner, 2026-11-20). VRPC has no 0.00000546 minimum. `vrpc/requests/preflight.js:421`. See [Funds 1](#funds-and-fees).
2. **Funding spends confirmed outputs only.** `getAddressUtxos.js` is equal to upstream: `getaddressutxos`, no mempool read, no own unconfirmed change (I5 (c), I6). A second send before the next block that the node refuses for spent inputs shows "Nothing new was sent". See [Funds 2](#funds-and-fees). Electrum is upstream code and still selects unconfirmed outputs (`getUnspent.js:81-91`).
3. **Balances are confirmed only (R13).** A VRPC balance is one `getaddressbalance`, no mempool read. One helper gives the confirmed value to every screen. See [Funds 3, 5](#funds-and-fees).
4. **New ETH and ERC-20 fee choice path.** Opt-in from the Send wizard only. See [Funds 6](#funds-and-fees).
5. **`sendrawtransaction` error -32603 is reported as "status unknown".** `vrpc/requests/send.js:73-78`. See [Broadcast 1](#transaction-building-and-broadcast).
6. **Request load (F3, F9-F14).** A 60 s `getinfo` height poll on the coin screen replaces the 15 s balance poll of earlier redesign builds. `listcurrencies` and static currency definitions are saved. Convert asks up to 30 `estimateconversion` per amount pause. See [Network 2, 3, 14](#network-and-refresh).
7. **30 s timeout on every VRPC and VerusID client, and address caches expire after a broadcast.** `vrpcInterface.js:43-44, 365-366`. See [Broadcast 2](#transaction-building-and-broadcast).
8. **GenericRequest signing order.** Identity and height are read first, then the key is requested. One signed response is kept per attempt and resent on retry. See [Keys 1-3](#keys-signing-and-authentication).
9. **Credential requests fail closed.** One unreadable stored credential fails the whole request; upstream skipped it. See [Keys 4](#keys-signing-and-authentication).
10. **Stored data that names the user is encrypted or in memory (R17-R22).** Asset choices are in the encrypted service data `wallet_asset_management`, with no migration code. See [Storage](#storage-and-migrations).
11. **Identity transfer refuses this wallet's own addresses.** Upstream allowed it. `recipient.js:13-25`. See [Funds 17](#funds-and-fees).
