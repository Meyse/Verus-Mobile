# Logic changes outside pure UI

This file lists every change in this pull request that is not pure layout, style or copy. It covers wallet logic, storage, network, Redux, native code and build files.

- Base: `upstream/ui-redesign` at `525aa859`. State described: the PR after the first round of review fixes (2026-11-18). Code locations are checked at `redesign` `06be68bd` (PR head `4a6da007` plus those fixes); see [DIFFERENCES_FROM_UPSTREAM.md](DIFFERENCES_FROM_UPSTREAM.md) for the three values that the PR keeps apart from `redesign`.
- `upstream/ui-redesign` is an ancestor of the head. No upstream commit is missing. Where the PR replaces recent upstream code on purpose, [DIFFERENCES_FROM_UPSTREAM.md](DIFFERENCES_FROM_UPSTREAM.md) gives the upstream commit and the reason.
- Review guide and UI areas: [README.md](README.md).

## How to read the tables

- **What changed** describes behavior against the base, not the commit history.
- **Why** gives the reason in one or two sentences, then the commit as a reference. The reason comes from the commit message, a code comment or a design record. "Reason not recorded" means none of these states it.
- Review IDs: `R` = review note, `I` = inline comment of the 2026-11-17 review. "Round 1" = the fixes of 2026-11-18. **Open** means the item waits for the owner's decision; the row describes the current code.
- **Evidence** gives the code location. Every row in the funds, keys and storage groups was checked in the source at that location. Rows marked "not verified" come from a diff reading only.
- "Test: none" means no Jest test or committed check script exercises the new behavior. Jest status for the whole branch is in [DIFFERENCES_FROM_UPSTREAM.md](DIFFERENCES_FROM_UPSTREAM.md#jest-status).
- No row changes key derivation, hash construction or encryption algorithms. Changes in the keys group are about order of steps, prompts, error codes and fail-closed checks.

## Read these first

These ten changes carry the highest risk. Each one links to its row.

1. **Native send rules are the upstream rules again (round 1, I5).** An amount above the balance is refused. An amount that fits the balance but not with the fee is lowered by the fee, and Confirm says so. The VRPC dust minimum is gone. `preflight.js:409-421`. See [Funds 1](#funds-and-fees). **Open (I5):** the reviewer asks to never change the output.
2. **Funding can spend the wallet's own unconfirmed change, and skips outputs spent in the mempool.** A failed mempool read blocks the send. `getAddressUtxos.js:35-62, 181-206`. Used by Send, Convert, identity updates, gift cards and claims. See [Funds 2](#funds-and-fees). **Open (I5, I6):** the reviewer asks to spend confirmed outputs only and to remove the mempool spend tracking.
3. **Pending balance and history grouping for VRPC.** `pending = total - confirmed`; extra uncached reads while the mempool is not empty; one history row per txid. `vrpc/updates.js:23-29, 83, 124-129`. See [Funds 3](#funds-and-fees). **Open (R13):** card totals include unconfirmed funds without a pending label.
4. **New ETH and ERC-20 fee choice path.** Gas limit, `maxFeePerGas`, MAX amount and a confirmed-fee check before signing. Opt-in from the new Send wizard only. See [Funds 6](#funds-and-fees).
5. **`sendrawtransaction` error -32603 is reported as "status unknown".** `vrpc/requests/send.js:73-78`. See [Broadcast 1](#transaction-building-and-broadcast).
6. **30 s timeout on every VRPC and VerusID client, and address caches expire after a broadcast.** `vrpcInterface.js:30-31, 48, 260, 505-507`. See [Broadcast 2](#transaction-building-and-broadcast).
7. **GenericRequest signing order.** Identity and height are read first, then the key is requested with the request context. One signed response is kept per attempt and resent on retry. `signGenericResponse.js:54-81`, `genericRequestDelivery.js:285-330`. See [Keys 1-3](#keys-signing-and-authentication).
8. **Credential requests fail closed.** One unreadable stored credential now fails the whole request; upstream skipped it. `scopedCredentials.js:197, 225`. See [Keys 4](#keys-signing-and-authentication).
9. **Asset choices are in plain AsyncStorage**, moved from encrypted service storage with a one-time migration. `assetManagementService.js:50, 123-167`. **Open (R17):** the reviewer asks to undo this. Since round 1, the other new stored data that names coins, addresses, balances or txids is encrypted or in memory only. See [Storage](#storage-and-migrations).
10. **Identity transfer refuses this wallet's own addresses.** A transfer to an address in this wallet, or to a VerusID whose primary addresses are all in this wallet, is refused. Upstream allowed it. `recipient.js:13-25`. See [Funds 17](#funds-and-fees).
